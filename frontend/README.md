# MarketHub frontend

Русскоязычный SPA: Vue 3, TypeScript strict, Vite, Vue Router, Pinia, Tailwind CSS 4, Axios и Lucide. Все бизнес-данные поступают из Laravel API, локальных фиктивных каталогов нет.

## Запуск на Windows

Основной адрес сайта — **http://markethub.test**. Vite для обычного запуска не нужен.

```powershell
cd D:\Projects\markethub\frontend
npm.cmd ci
npm.cmd run build
cd ..
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Зависимости устанавливаются один раз, сборка повторяется после изменений frontend. Если `frontend/dist` уже собран, достаточно выполнить `scripts/start.ps1` из корня проекта. По умолчанию используется `infra/nginx-spa.conf`. PostgreSQL и Memurai должны работать, в hosts нужна запись `127.0.0.1 markethub.test`.

Для остановки: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop.ps1` из корня проекта.

Для разработки с автоматическим обновлением дополнительно запустите `npm.cmd run dev` в `frontend/` и откройте `http://127.0.0.1:5173`. Оба режима используют тот же backend. Флаг `scripts/start.ps1 -BackendOnly` запускает исходный API-конфиг без SPA.

Войти можно существующей учётной записью организации. Пароли не изменяются, регистрация отсутствует. Создание локального пользователя и привязка к демо описаны в корневом README.

## Структура и страницы

```text
frontend/
  src/
    api/                  # Axios, auth, products, marketplaces, stocks
    assets/main.css       # Tailwind и стили адаптивного интерфейса
    components/ui/        # состояния, пагинация, ошибки полей
    layouts/AppLayout.vue # меню, пользователь, выбор организации
    pages/                # страницы SPA
    router/               # маршруты и проверка сессии
    stores/auth.ts        # пользователь и восстановление cookie-сессии
    types/                # типы реальных API-ответов
    utils/                # точное преобразование денег и тесты
  e2e/app.spec.ts          # проверка браузера с реальным backend
```

| Адрес                    | Возможности                                                                         |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `/`                      | Публичная главная, описание возможностей и деморежима                               |
| `/login`                 | Cookie-вход Sanctum, ошибки валидации                                               |
| `/app`                   | Счётчики каталога из `meta.total`, состояния загрузки и пустого каталога            |
| `/app/products`          | Поиск, активность, сортировка, пагинация, подтверждение удаления                    |
| `/app/products/new`      | Создание товара                                                                     |
| `/app/products/:id`      | Карточка товара и переход к остаткам                                                |
| `/app/products/:id/edit` | Редактирование товара                                                               |
| `/app/marketplaces`      | Список, создание и редактирование подключений                                       |
| `/app/stocks`            | Поиск, фильтр маркетплейса и остатков, пагинация, выделение нулевых/низких остатков |
| Остальные адреса         | Страница 404                                                                        |

## API-контракт

Полный исходный контракт: [API.md](../docs/API.md) и [openapi.json](../docs/openapi.json).

| Endpoint                                   | Использование SPA                                              |
| ------------------------------------------ | -------------------------------------------------------------- |
| `GET /sanctum/csrf-cookie`                 | CSRF перед входом, сохранением и выходом; обновление после 419 |
| `POST /api/v1/auth/login`                  | Вход email/password                                            |
| `GET /api/v1/auth/me`                      | Восстановление пользователя при обновлении страницы            |
| `POST /api/v1/auth/logout`                 | Завершение сессии                                              |
| `GET /api/v1/organizations`                | Пагинированный список доступных организаций                    |
| `PATCH /api/v1/organizations/active`       | Смена организации и перезагрузка данных страницы               |
| `GET, POST /api/v1/products`               | Список, счётчики, создание                                     |
| `GET, PATCH, DELETE /api/v1/products/{id}` | Просмотр, редактирование, удаление                             |
| `GET, POST /api/v1/marketplace-accounts`   | Список, счётчик, создание подключения                          |
| `PATCH /api/v1/marketplace-accounts/{id}`  | Редактирование подключения                                     |
| `GET /api/v1/stocks`                       | Просмотр остатков и счётчик размещений без остатка             |

В backend также есть GET/DELETE отдельного подключения и полный CRUD `/api/v1/marketplace-listings`. Эти операции не нужны текущим страницам. `GET /api/system-checks` и `/up` — технические проверки.

Все списки используют Laravel `data`, `links`, `meta`; по умолчанию загружается 20 записей. Счётчики запрашивают `per_page=1`, включая `is_active=1` и `stock=zero`, без выгрузки каталога. `price_minor` преобразуется через десятичные строки и `BigInt`; дробная арифметика не используется. Валидационные ошибки 422 показываются у полей, 409 сообщает о зависимых записях, 401 направляет на вход. При 419 CSRF-cookie обновляется, а отклонённое действие пользователь повторяет явно; автоматического повторного сохранения нет.

## Cookies, proxy и Sanctum

`VITE_API_BASE_URL` по умолчанию `/`; образец — `.env.example`. Это базовый адрес сервера, без суффикса `/api/v1`. Для обычной разработки менять его не нужно.

Vite проксирует `/api` и `/sanctum` на `http://markethub.test`. Proxy устанавливает backend Host и Origin/Referer `http://markethub.test`, поэтому существующий stateful domain подходит. Cookie возвращаются на origin Vite и отправляются Axios вместе с X-XSRF-TOKEN. Локальный proxy слушает только loopback. Проверять браузерную интеграцию следует через Vite, а не через `vite preview`, у которого такой proxy не настроен.

Для этой схемы backend менять не требуется: существующие `SANCTUM_STATEFUL_DOMAINS=markethub.test,...`, `SESSION_DOMAIN=null`, `FRONTEND_URL=http://markethub.test` подходят. CORS браузер не пересекает. При переходе к прямым запросам на отдельный origin нужно отдельно согласовать CORS, stateful domains, same-site домен и cookies; одного изменения base URL недостаточно. Токены и пароли в localStorage не сохраняются.

## Production и Nginx

```powershell
cd D:\Projects\markethub\frontend
npm.cmd run build
```

Результат — `frontend/dist`. Отдельный полный конфиг [nginx-spa.conf](../infra/nginx-spa.conf) подготовлен на основе существующего. Он отдаёт SPA из dist с fallback на index.html; `/api`, `/sanctum` и `/up` направляются в исходный Laravel public/index.php. PHP-файлы и скрытые пути закрыты. Исходный `infra/nginx.conf` не изменён.

Обычный `scripts/start.ps1` уже подключает этот конфиг. Ручное переключение Nginx не требуется. Если ранее запущен старый экземпляр, сначала выполните `scripts/stop.ps1`, затем `scripts/start.ps1`. На внешнем production нужны HTTPS, secure cookies и домены реального окружения.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd audit
# При запущенных backend и Vite:
npm.cmd run test:e2e
```

E2E использует установленный Google Chrome и PHP `C:/tools/php83/php.exe`. Разрешён только для local/PostgreSQL: создаёт случайную временную учётную запись с членством в первой существующей организации, проверяет реальные данные и создаёт собственные тестовые записи. В afterAll удаляет записи по случайному SKU/имени и временного пользователя. Существующие учётные записи, пароли и бизнес-записи не меняет. Пароль генерируется в памяти. Запускать на локальном демоокружении с товарами, остатками и подключениями. Для другой машины поправьте путь PHP и канал браузера в конфигурации теста.

## Ограничения API

- Нет агрегата уникальных товаров с нулевым остатком: показываем честный счётчик **размещений** без остатка. Для числа товаров нужен отдельный агрегирующий endpoint.
- Нет API продаж, заказов, выручки и аналитики — соответствующие рабочие разделы и графики не добавлены.
- Нет безопасного хранения ключей и внешних интеграций WB/Ozon — поля API-ключей отсутствуют.
- Нет публичной регистрации, восстановления пароля и управления ролями — интерфейс их не имитирует.
- Остатки доступны только для просмотра; отдельная frontend-модель складского учёта не создаётся.

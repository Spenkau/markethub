# Shopify → MarketHub

Реализовано по TASK7; переход на общий backend-фундамент описан в [TASK8](architecture/marketplace-foundation-task8.md). Shopify — реальный источник данных в существующих подключениях, товарах и размещениях. GraphQL Admin API `2026-10`; направление только Shopify → MarketHub. Заказы, webhooks и изменение данных Shopify в эту версию не входят.

## Использование

В «Маркетплейсах» нажмите «Добавить подключение», выберите Shopify, укажите название, домен `*.myshopify.com`, Client ID и Client Secret установленного приложения с client credentials grant. Требуются `read_products`, `read_inventory`, `read_locations`. Кнопка проверки показывает доступность API и недостающие права. Несколько магазинов имеют независимые подключения, настройки, токены и историю.

По умолчанию: `hourly`, товары и остатки включены. Первый импорт требует отдельного подтверждения. До его успешного завершения автоматические задания не создаются. Настройки `manual` / `hourly` / `daily` и два независимых переключателя применяются без перезапуска. При двух выключенных переключателях импорт не запускается.

Страница `/app/marketplaces/shopify/:id` содержит обзор, товары, внешние остатки, настройки и историю. Форма создания общая с остальными площадками; прежний URL `/app/marketplaces/shopify/new` перенаправляет в неё. В каталоге доступны фильтры источника и подключения; карточка товара содержит ссылки на Shopify-размещения. Внешние остатки открываются из раздела складов. Экскурсия Shopify доступна через существующий модуль обучения.

Учётные данные шифруются Laravel `encrypted` casts; ключ `APP_KEY` необходимо сохранять вместе с резервной копией. Credentials и токены не возвращаются браузеру и не включаются в диагностику. Токен кешируется зашифрованным, отдельно по организации, подключению и версии credentials. Проверка домена и запрет перенаправлений ограничивают отправку credentials доменом магазина Shopify.

Для уже имеющегося локального файла credentials доступна команда (только `APP_ENV=local`):

```powershell
php artisan shopify:connect-local D:\Projects\credentials.txt --organization=1
```

Команда проверяет API и сохраняет подключение, но не запускает импорт. Не добавляйте файл credentials в Git. В текущей локальной базе подключён реальный магазин `markethub`, ID подключения `15`.

## Хранение и сопоставление

Изменены существующие таблицы:

- `marketplace_accounts`: Shopify-домен, зашифрованные credentials, настройки, права и состояние API, время первого/последнего/следующего импорта.
- `marketplace_listings`: nullable `product_id` для несопоставленных вариантов, nullable внешний остаток, исходные данные JSON, статус источника и время обновления. Несколько вариантов одного магазина могут ссылаться на один локальный товар. Прежнее ограничение WB/Ozon сохраняется частичным уникальным индексом.

Созданы:

- `shopify_sync_runs`: UUID запуска, настройки на момент запуска, режим полной сверки, статусы и счётчики, ограниченная безопасная диагностика.
- `shopify_locations`: локации конкретного подключения; nullable `warehouse_id` предусмотрен для будущего сопоставления со складами.
- `shopify_inventory_levels`: внешний снимок по варианту и локации, `available`, `on_hand`, `committed`, `incoming`, tracked, время источника и получения, признак актуальности.

Миграции не удаляют существующие данные. После TASK8 внешние родители нормализуются в `marketplace_products`, варианты остаются в `marketplace_listings`. Обычный импорт больше не создаёт локальные SKU и не изменяет product_id: новые варианты остаются несопоставленными. Создать локальную SKU можно явным `POST /api/v1/marketplace-listings/{id}/local-product`, либо сопоставить с существующим товаром. Совпадение SKU/названия не объединяет товары. Ранее созданные local products и mapping сохранены. Canonical credentials находятся в `marketplace_credentials` в зашифрованной payload; legacy encrypted поля сохранены для совместимости.

Повторный импорт обновляет внешние данные размещения, сохраняя редактируемые локальные поля. Сохраняются product/variant GID, описание, handle, vendor, product type, статус, изображения, SKU, barcode, цены, inventory item и даты источника. Неизвестное или неотслеживаемое количество — `null`, а не ноль. Отрицательное доступное количество сохраняется во внешнем снимке, но не подставляется в неотрицательный агрегат размещения.

`warehouse_stocks` и складские движения импорт не изменяет. Остатки Shopify только для чтения, с указанием локации и даты. Старые снимки после исчезновения локации/размещения сохраняются с признаком неактуальности.

## Выполнение и расписание

HTTP-запуск возвращает `202` и UUID, затем `SyncShopify` выполняется в Redis-очереди `shopify`. Настройки копируются в запуск. Статусы: `queued`, `running`, `completed`, `partial`, `failed`. Частичная ошибка сохраняет корректно обработанные записи; критическая ошибка не считается успехом. История содержит обработанные товары, варианты и остатки, созданные/обновлённые/пропущенные размещения, ошибки и длительность. Суммарный `processed` — варианты плюс обработанные inventory items, это не количество уникальных товаров.

Постранично обходятся products, images, variants, locations (включая inactive и legacy fulfillment locations), inventory levels. Каталог целиком в память не загружается. Первый импорт полный; затем products фильтруются по `updated_at` с перекрытием 5 минут. Не реже суток выполняется полная сверка для обнаружения удалений. Отсутствующее размещение помечается удалённым только после успешного обхода соответствующих страниц; локальный товар сохраняется. Временная ошибка API не служит основанием для удаления.

Есть обновление токена при 401, ограниченные повторы сетевых ошибок, HTTP 429/5xx и GraphQL throttling с задержкой. Job: до трёх попыток, timeout 1800 секунд; Redis `retry_after=1900`. Уникальный частичный индекс и блокировка строки подключения защищают очередь от дублей; PostgreSQL advisory lock защищает выполнение. Завершённое задание повторно не импортируется. Зависшие задания старше 35 минут обнаруживаются диспетчером. Ошибка после уже успешного первого импорта откладывает следующий запуск примерно на час.

Laravel Scheduler каждую минуту выполняет `shopify:dispatch-due`, проверяет PostgreSQL `next_sync_at` и ставит задания только для активных подключений с завершённым первым импортом. После успеха новое время — час или сутки от завершения. `manual` и выключенные типы данных исключаются. Смену настроек проверяет каждый следующий проход, без отдельного процесса на магазин.

## Windows: запуск фоновых процессов

Необходимы запущенные PostgreSQL и Redis/Memurai, `.env` с `QUEUE_CONNECTION=redis`, миграции и сборка frontend:

```powershell
cd D:\Projects\markethub
php artisan migrate
cd frontend
npm.cmd run build
cd ..
powershell -ExecutionPolicy Bypass -File scripts\shopify-workers.ps1 -Action Start
powershell -ExecutionPolicy Bypass -File scripts\shopify-workers.ps1 -Action Status
```

Скрипт использует установленный `C:\tools\php83\php.exe`, запускает два скрытых процесса, сохраняет их PID и время создания в игнорируемом `infra/runtime/shopify-workers.json`. Логи находятся рядом, в `shopify-worker*.log` и `shopify-scheduler*.log`. После обновления backend-кода перезапустите процессы:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\shopify-workers.ps1 -Action Stop
# Дождитесь завершения текущего задания и проверьте Status.
powershell -ExecutionPolicy Bypass -File scripts\shopify-workers.ps1 -Action Start
```

Эквивалентный ручной запуск в двух терминалах:

```powershell
php artisan queue:work redis --queue=shopify --sleep=3 --tries=3 --timeout=1800
php artisan schedule:work
```

Для запуска после входа Windows создайте задачу в «Планировщике заданий»: триггер «При входе в систему», программа `powershell.exe`, аргументы `-NoProfile -ExecutionPolicy Bypass -File "D:\Projects\markethub\scripts\shopify-workers.ps1" -Action Start`, рабочая папка `D:\Projects\markethub`. PostgreSQL и Memurai должны запускаться службами. Автозапуск Windows не регистрируется миграцией. Альтернатива — задача каждую минуту для `php artisan schedule:run`, но одновременно с `schedule:work` её запускать не следует. Worker всё равно нужен отдельно.

При выключенном ПК, остановленном Redis, worker или scheduler автоматического обновления нет. Задания продолжатся после запуска процессов; запоздавшее расписание обрабатывается следующим проходом. На этой машине TLS потребовал CA-файл Git: в локальном `.env` задан `SHOPIFY_CA_BUNDLE=C:/Program Files/Git/usr/ssl/certs/ca-bundle.crt`; проверка TLS не отключается. На другой машине используйте доверенный актуальный CA bundle или штатный trust store PHP.

## API

Все endpoints требуют Sanctum и активную организацию. База: `/api/v1/shopify/connections`.

| Метод и путь | Назначение |
| --- | --- |
| POST `/` | Создать подключение: name, shop_domain, client_id, client_secret |
| GET `/{account}` | Настройки и сводка без credentials |
| PATCH `/{account}` | Имя, статус, frequency, переключатели, новые credentials |
| POST `/{account}/check` | Проверить API и текущие права |
| POST `/{account}/sync` | Поставить импорт; при первом запуске `confirm_initial_import: true` |
| GET `/{account}/products` | Варианты, локальное сопоставление, исходные данные |
| PATCH `/{account}/products/{listing}/mapping` | Сопоставить: `product_id` или null |
| GET `/{account}/inventory` | Внешние снимки остатков |
| GET `/{account}/locations` | Локации подключения |
| GET `/{account}/runs` | История запусков |
| GET `/{account}/runs/{uuid}` | Детали запуска |

Подключения перечисляются прежним `GET /api/v1/marketplace-accounts?marketplace=shopify`. Товары каталога поддерживают `marketplace=shopify` и `marketplace_account_id`. Списки Shopify используют `page`, `per_page`; товары — `search`, `status`, `mapping`; остатки — `search`, `location_id`, `product_id`; история — `status`, `trigger`, `date_from`, `date_to` (UTC). Изменение/удаление импортированных размещений через прежний CRUD запрещено. Общий раздел «Остатки площадок» и его Excel-экспорт включают Shopify; неизвестное количество остаётся пустым/null.

## Ограничения и следующие этапы

Создание локального товара на вариант требует явного действия; внешние родители и их варианты нормализованы, локальная группировка SKU ещё не реализована. Сопоставление locations со складами пока представлено полем в схеме. Импорт выполняется страницами в одном ограниченном по времени задании: для каталога, не укладывающегося в 30 минут, следующим этапом нужны возобновляемые задания по страницам или Bulk Operations. Webhooks, заказы и запись в Shopify требуют отдельного этапа. История хранит первые 100 диагностических сообщений каждого запуска, полные credentials/ответы не журналируются.

Официальная документация: [client credentials grant](https://shopify.dev/docs/apps/build/authentication-authorization/access-tokens/client-credentials-grant), [GraphQL Admin API](https://shopify.dev/docs/api/admin-graphql/2026-10), [пагинация](https://shopify.dev/docs/api/usage/pagination-graphql), [лимиты API](https://shopify.dev/docs/api/usage/limits).

## Страница варианта и точечное обновление

Каждый вариант открывается по `/app/marketplaces/shopify/:account/products/:listing`. Страница содержит галерею с крупным просмотром, цену и SKU источника, сопоставление с каталогом и внешние остатки по локациям. В списке товаров превью увеличены до 96 px. Сопоставление и переход в Shopify — отдельные действия; выбор локального товара теперь показывает список с видимой пагинацией.

Для изменения товара откройте «Редактировать в Shopify», сохраните изменения в Shopify и нажмите «Обновить из Shopify» в MarketHub. Запрос `POST /api/v1/shopify/connections/{account}/products/{listing}/refresh` возвращает 202 и ставит задание с `target_listing_id`. Выполняется запрос productVariant по GID и обновление inventory только выбранного варианта. Локальные поля не перезаписываются; глобальные watermarks и расписание магазина не сдвигаются. Одновременный полный импорт исключён общей блокировкой подключения. Данные карточки: `GET /api/v1/shopify/connections/{account}/products/{listing}`. Миграция `000003` добавляет nullable FK `shopify_sync_runs.target_listing_id`.

Проверка доработок: 97 backend-тестов / 782 assertions, дополнительно 4 теста экспорта / 57 assertions. Реальный запуск `64fae450-0672-4997-b68e-a9e6e5f69763` завершён без ошибок: один вариант и один inventory item.

# MarketHub: рабочий интерфейс CRM

Vue 3 + TypeScript, существующий Laravel REST API и Sanctum сохранены. Новых зависимостей и шаблонов административных панелей нет. Основная тема кабинета находится в `frontend/src/assets/workspace.css`; публичные страницы используют прежнюю структуру.

## Реальные данные

| Элемент | Источник | Что означает |
| --- | --- | --- |
| Товары / активные товары | GET /api/v1/products, is_active=1 | meta.total всей организации |
| Размещения | GET /api/v1/stocks | meta.total, не сумма единиц товара |
| Проблемные остатки | stocks?stock=zero и stock=low | Нулевой остаток и 1–5 единиц, все статусы размещений |
| Диаграмма наличия | Те же totals | Текущий срез: 0 / 1–5 / более 5 единиц |
| Активность каталога | products totals | Доля активных товаров; это не динамика продаж |
| Подключения | GET /api/v1/marketplace-accounts | Количество и сохранённые локальные статусы |
| Список подключений на обзоре | marketplace-accounts?sort=created_at&direction=desc&per_page=4 | Четыре последних подключения |
| Недавно добавлены | products?sort=created_at&direction=desc&per_page=5 | Пять последних товаров по created_at, без выдуманных авторов действий |
| Время обновления | Время успешного запроса в браузере | Не время синхронизации с маркетплейсом |

Страницы товаров и остатков показывают общее число по фильтрам из meta.total. Дополнительные показатели явно подписаны «на странице» и вычисляются только по текущей странице. Они не выдают выборку за весь каталог. В маркетплейсах количества Ozon и Wildberries относятся ко всей организации, независимо от фильтров списка. Если запрос не удался, отсутствующие значения показаны как «—».

## Изменения интерфейса

- Общая тема: тёмная боковая навигация, светлая рабочая область, индиго как основной акцент, единые карточки, кнопки, отступы, таблицы и статусы.
- Обзор: четыре KPI, две диаграммы текущего состояния, приоритетные остатки, подключения и новые товары. Переходы ведут к подходящим фильтрам и карточкам.
- Товары: сводка, сброс фильтров, дата обновления, переход к размещениям, выбор размера страницы. Создание, редактирование, удаление и экспорт сохранены.
- Остатки: фильтр статуса, сортировка и направление, размер страницы, фильтры товара и аккаунта с явным контекстом и сбросом. XLSX использует те же фильтры.
- Маркетплейсы: поиск, фильтры площадки, статуса и режима, сортировка; локальные статусы, число размещений, дата обновления и переход к размещениям аккаунта.
- Общие состояния: skeleton загрузки, ошибка с повтором, пустая выборка. Мобильное меню, адаптивные карточки, прокрутка таблиц внутри панели, клавиатурный переход к содержимому и поддержка reduced motion.

## Данные, которых пока нет

Выручка, количество заказов, средний чек, конверсия, возвраты, прибыль и временные ряды продаж отсутствуют. Результаты внешней синхронизации и журнал действий отсутствуют. UI не рисует для них цифры и не показывает успешную синхронизацию на основании локального статуса «Активно».

Минимальные предложения API (не реализованы в рамках обновления frontend):

1. `GET /api/v1/dashboard/summary` — одним запросом вернуть counts товаров/размещений/аккаунтов и распределения остатков. Это оптимизация существующих данных: сейчас обзор использует восемь небольших запросов списков. Ответ должен вычисляться в активной организации и проверять права на каждый ресурс.
2. `GET /api/v1/activity?cursor=...&limit=10` — после добавления журнала возвращать id, actor, action, entity_type, entity_id, display_name и occurred_at. Только этот источник позволит показать «последние действия» с авторами, изменениями и удалениями. created_at товара не заменяет журнал.
3. `GET /api/v1/marketplace-accounts/{id}/sync-status` — после реализации интеграций: last_attempt_at, last_success_at, state, безопасное error_message. До появления интеграции возвращать state=not_configured и null даты.
4. `GET /api/v1/analytics/sales?from=...&to=...&group_by=day&marketplace=...` — только после появления заказов: totals и series с orders_count, revenue_minor, currency. Разные валюты считать отдельно; даты и часовой пояс задавать явно. До подключения источника возвращать available=false и пустые значения, а не фиктивные нули или проценты роста.

Все предложенные endpoints требуют Sanctum, активной организации и существующих Policies. Реальные интеграции, модель заказов и журнал действий — отдельная backend-задача.

## Складской учёт

Физические остатки теперь находятся в отдельном разделе `/app/stocks`, а прежние остатки размещений перенесены на `/app/marketplace-stocks`. На обзоре добавлен независимый блок складских показателей из `/api/v1/warehouse-stocks/summary`. Подробности операций и API: [WAREHOUSES.md](WAREHOUSES.md).
